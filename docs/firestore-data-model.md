# Firestore data model

Ticknest stores each workspace's business data under its workspace document. Firestore Rules and callable functions use the workspace ID as the authorization boundary.

## Collections

| Path                                                  | Document fields                                                                                                                                                                           | Notes                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users/{uid}`                                         | `displayName`, `email`, `timezone`, optional `palette`, `createdAt`, `updatedAt`                                                                                                          | Private profile; a user can read and update only their own profile. The email is a display copy, not an identity authority. `palette` is the user's color palette (`system`, `forest`, `ocean`, `plum`, `terracotta`, `forest-night`, `midnight`, or `graphite`); a missing value means the default, `forest`. |
| `workspaces/{workspaceId}`                            | `name`, `ownerUid`, `weekStartsOn`, `createdAt`, `updatedAt`                                                                                                                              | `ownerUid` is assigned by a trusted callable function and cannot be changed from the browser.                                                                                                                                                                                                                  |
| `workspaces/{workspaceId}/members/{uid}`              | `uid`, `email`, `displayName`, `role`, `status`, `joinedAt`, optional `removedAt`                                                                                                         | Role is `owner` or `member`; status is `active` or `removed`. Callable functions are the only writers. Removed member records remain as historical attribution, while security rules deny them workspace access.                                                                                               |
| `workspaces/{workspaceId}/invitations/{invitationId}` | `email`, `role`, `tokenHash`, `expiresAt`, `status`, `createdBy`, `createdAt`, optional `acceptedBy`, `acceptedAt`, `revokedAt`                                                           | Invitation writes are reserved for trusted functions. The accept flow verifies the authenticated, verified email and single-use expiration in a transaction.                                                                                                                                                   |
| `workspaces/{workspaceId}/clients/{clientId}`         | `name`, `archived`, `createdAt`, `updatedAt`                                                                                                                                              | Owners manage records; all members can read them.                                                                                                                                                                                                                                                              |
| `workspaces/{workspaceId}/projects/{projectId}`       | `name`, `clientId`, `description`, `color`, `estimateMinutes`, `archived`, `createdAt`, `updatedAt`                                                                                       | `clientId` is optional and workspace-scoped.                                                                                                                                                                                                                                                                   |
| `workspaces/{workspaceId}/tasks/{taskId}`             | `name`, `projectId`, `estimateMinutes`, `billable`, `archived`, `createdAt`, `updatedAt`                                                                                                  | Each task belongs to a project in the same workspace. `billable` is the default for entries tracked against the task; tasks saved before it existed may lack it and read as non-billable.                                                                                                                      |
| `workspaces/{workspaceId}/timeEntries/{entryId}`      | `userId`, `userDisplayName`, `description`, optional association IDs and display snapshots, `startAt`, nullable `endAt`, nullable `durationSeconds`, `billable`, `createdAt`, `updatedAt` | Instants are Firestore timestamps. A running entry has a null `endAt` and `durationSeconds`; a completed entry has an end after its start and a positive duration.                                                                                                                                             |
| `workspaces/{workspaceId}/timeEntryLocks/{uid}`       | `updatedAt`                                                                                                                                                                               | Written only by the `saveManualTimeEntry` callable. Every manual create or edit for a user reads and writes this document in its transaction, so concurrent saves for the same user are serialized and cannot both pass the overlap check. Clients cannot read or write it.                                    |

All audit timestamps are written with server timestamps. Workspace and association names are bounded strings. Unknown fields are rejected by rules. Entries retain display snapshots so archival of a client, project, or task does not erase historical context.

## Trusted writes

The browser must not write workspace owner identity, membership role or membership documents, or invitation documents. Callable Cloud Functions derive the user ID and email from the verified Firebase Auth token. `createWorkspace`, `createWorkspaceInvitation`, `revokeWorkspaceInvitation`, `removeWorkspaceMember`, and `acceptWorkspaceInvitation` validate authority and write membership/invitation state through trusted code. `saveManualTimeEntry` creates and edits completed time entries: it checks membership and ownership, resolves catalog display names from the referenced client, project, and task, and rejects overlaps with the user's other entries or running timer in the same transaction as the write. Firebase Admin credentials remain in the managed function runtime. Invitation tokens are single-use, high-entropy values; only their SHA-256 hashes are stored, and invitations expire after seven days.

Cloud Functions deployment currently requires Firebase's Blaze plan and a linked billing account. The plan has a no-cost usage quota, but exceeding its included usage can incur charges. See Firebase's [pricing-plan documentation](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans).

## Security rules

- Workspace documents can be read only by members. Owners can update only the workspace name, week start, and update timestamp; ownership cannot be changed by a client.
- Members can read workspace clients, projects, and tasks. Members can read only their own time entries; owners can read every workspace time entry. Firestore queries by members must constrain `userId` to their authenticated UID.
- Owners can create, update, and delete clients, projects, and tasks.
- Members can start and stop their own timers directly. Completed entries are created and edited only through the `saveManualTimeEntry` callable, so overlap validation cannot be bypassed or raced; members can edit only their own entries there and owners can edit any member's entries. Members can delete their own completed entries and owners can delete any completed entry. Entry ownership cannot be changed by a client.
- Membership and invitation writes are denied to all web clients. Callable functions use the Admin SDK, which bypasses Firestore Rules, so those functions validate every input and check the authenticated user themselves.
- Unmatched collections and documents are denied by default.

## Indexes

The user workspace selector uses a collection-group query on `members` constrained by `uid == currentUser.uid`; the single-field collection-group index is managed by Firestore. Add composite indexes alongside future queries when those features are implemented.
